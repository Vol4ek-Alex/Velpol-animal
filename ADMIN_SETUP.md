# 🔐 Инструкция по настройке администратора

## 📋 Проблема и решение

**Проблема:** После регистрации пользователь получает письмо подтверждения, но при клике на ссылку происходит ошибка redirect на localhost.

**Решение:** Настроить Supabase redirect URL и создать администратора для одобрения пользователей.

---

## 🚀 Шаг 1: Настройка Supabase

### 1.1 Выполнить SQL-скрипт

1. Откройте **Supabase Dashboard** → ваш проект
2. Перейдите в **SQL Editor**
3. Скопируйте и выполните содержимое файла `supabase-schema.sql`
4. Нажмите **RUN** для создания таблиц и политик безопасности

### 1.2 Настроить Redirect URL

1. В Supabase Dashboard перейдите в **Authentication** → **URL Configuration**
2. Добавьте URL подтверждения email в **Redirect URLs**:
   ```
   https://ваш-домен.vercel.app/confirm-email.html
   ```
   
   Например:
   ```
   https://velpol-animal.vercel.app/confirm-email.html
   ```

3. Для локальной разработки также добавьте:
   ```
   http://localhost:3000/confirm-email.html
   ```

4. Нажмите **Save**

### 1.3 Настроить Email Template (опционально)

В **Authentication** → **Email Templates** → **Confirm signup**:

Убедитесь что там есть ссылка:
```html
<a href="{{ .ConfirmationURL }}">Подтвердить Email</a>
```

## 👤 Шаг 2: Создание первого администратора

### 2.1 Зарегистрировать первого пользователя

1. Перейдите на ваш сайт
2. Выберите любой модуль (например, Агрономия)
3. Нажмите **Регистрация**
4. Заполните форму:
   - **Полное имя**: Администратор
   - **Email**: ваш email
   - **Пароль**: минимум 6 символов
5. Подтвердите email по ссылке из письма

### 2.2 Найти User ID

1. В Supabase Dashboard → **Authentication** → **Users**
2. Найдите вашего пользователя
3. Скопируйте **User ID** (UUID, например: `a1b2c3d4-e5f6-7890-abcd-ef1234567890`)

### 2.3 Предоставить права администратора

⚠️ **ВАЖНО:** Если вы создали таблицу `module_access` до обновления схемы, сначала исправьте constraint:

#### Вариант A: Если получаете ошибку "violates check constraint"

1. Перейдите в **SQL Editor**
2. Выполните содержимое файла **`ADMIN_FIX.sql`** (это исправит constraint)
3. Замените `'ВАШ_USER_ID'` на ваш UUID и выполните

#### Вариант B: Если таблица создана правильно

1. Перейдите в **SQL Editor**
2. Выполните SQL:

```sql
INSERT INTO module_access (user_id, module_name, has_access)
VALUES ('ВАШ_USER_ID', 'admin', true);
```

**Замените `ВАШ_USER_ID`** на скопированный UUID!

Пример:
```sql
INSERT INTO module_access (user_id, module_name, has_access)
VALUES ('a1b2c3d4-e5f6-7890-abcd-ef1234567890', 'admin', true);
```

3. Нажмите **RUN**

## 🎯 Шаг 3: Использование админ-панели

### 3.1 Доступ к админ-панели

URL админ-панели:
```
https://ваш-домен.vercel.app/admin/
```

Или локально:
```
http://localhost:3000/admin/
```

### 3.2 Одобрение пользователей

1. Войдите на сайт как администратор
2. Перейдите в админ-панель по URL выше
3. Вы увидите список всех заявок на доступ
4. Для каждой заявки доступны действия:
   - ✅ **Одобрить** - предоставить доступ к модулю
   - ❌ **Отклонить** - отказать в доступе

### 3.3 Что происходит при одобрении

1. Статус заявки меняется на "Одобрено"
2. Пользователь получает доступ к выбранному модулю
3. Теперь он может войти в систему и использовать модуль

---

## 🔄 Процесс регистрации пользователя

1. **Пользователь регистрируется** → выбирает модуль и заполняет форму
2. **Система создаёт заявку** → запись в `pending_access_requests`
3. **Отправка письма** → Supabase отправляет письмо подтверждения
4. **Подтверждение email** → пользователь кликает на ссылку в письме
5. **Редирект** → перенаправление на `confirm-email.html` (больше не ошибка localhost!)
6. **Ожидание одобрения** → пользователь видит сообщение "Ожидает одобрения администратора"
7. **Администратор одобряет** → в админ-панели
8. **Доступ предоставлен** → пользователь может войти в модуль

## 🆘 Решение проблем

### Проблема: "У вас нет прав администратора"

**Решение:** Проверьте что вы выполнили SQL для создания администратора:
```sql
SELECT * FROM module_access WHERE module_name = 'admin';
```

Если пусто - выполните INSERT из шага 2.3

### Проблема: Всё ещё редирект на localhost

**Решение:** 
1. Проверьте что добавили URL в Supabase → Authentication → Redirect URLs
2. URL должен совпадать с вашим доменом
3. Попробуйте очистить кэш браузера

### Проблема: Заявки не отображаются в админке

**Решение:**
1. Проверьте что SQL-скрипт выполнен полностью
2. Проверьте RLS политики:
```sql
SELECT * FROM pending_access_requests;
```
